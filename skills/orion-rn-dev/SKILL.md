# Orion React Native development

Expo + React Native, **Android only** — iOS ships from the Swift repos. The
`ios/` directory is gitignored and the `ios` npm script is vestigial.

Read [../orion-design-system/references/react-native.md](../orion-design-system/references/react-native.md)
for anything that renders. This skill is the architecture and the workflow.

## Before you search

Three full checkouts live under `.claude/worktrees/`. A naive grep returns
**four copies of every file**, and editing the wrong one wastes the change:

```bash
grep -r "pattern" app components --include="*.tsx" | grep -v '/.claude/worktrees/'
```

## Golden rules

Violating these breaks builds or ships bugs.

1. **Never hand-edit `android/`.** It is committed but regenerated by prebuild.
   Change `app.config.js`, `plugins/*.js` or `native-modules/*`, then
   `npx expo prebuild --platform android`.
2. **Never hand-edit `unistyles.ts`.** Generated by `npm run sync:tokens`. The
   file carries no banner — its silence is not permission.
3. **Never reorder `index.ts` imports.** `./installNitroFetch` must stay first.
4. **New persisted store ⇒ update `purgeAllStorage`** (`utils/storage/common.ts`),
   or user data leaks across logout and account-swap.
5. **New LaunchDarkly flag ⇒ registry + typed hook** (`config/featureFlags.ts`,
   `hooks/useLaunchDarkly.ts`). Never inline a flag string.
6. **New user-facing string ⇒ i18n.** New namespace ⇒ register it in
   `i18n/index.ts`, and get eager-vs-deferred right (see below).
7. **Device writes go through the optimistic lock/debounce pattern**
   (`useDeviceControl`, the store helpers). Never fire raw REST from a
   component; never send commands over the WebSocket.
8. **API results are envelopes.** The axios interceptor already unwrapped
   `.data`, so every call resolves to `{ response, success, error }` — check
   `success` before reading `response`.
9. **Colours, spacing and text via `theme.*` and the typography primitives.**
10. **Don't remove weird-looking workarounds.** The BLE null-error
    normalization, the nitro-fetch gzip bypass, the OneSignal 1.5s delay, the
    Intercom login sleeps, the Android-16 `Connection: close`, the Reanimated
    `?? fallback` reads — all load-bearing, all documented in-code.

## Verifying a change

There are **no tests** — no jest, no testing-library, no detox, no `__tests__`
anywhere. And until now, **no CI**. The gates are:

```bash
npx tsc --noEmit          # there is no `typecheck` script; type it out
npm run lint              # expo lint
npm run format            # prettier
python3 scripts/check_design.py --platform rn
```

Then run it on a device. Never claim test coverage in a PR.

`npm run screenshot` pulls a screencap off the connected device to `~/Desktop`.

## The stack

| Concern | Library | Convention |
|---|---|---|
| Routing | `expo-router` (typed routes) | File-based, 13 route groups. Every `_layout` sets `headerShown: false`; screens compose `NavigationBar` + `Header`. `router.push(path as any)` is the sanctioned escape hatch. |
| State | `zustand` | `useXxxStore` naming, `persist` + `createJSONStorage(mmkvStorageAdapter)`. **No barrel export** — import by path. |
| Storage | `react-native-mmkv`, `expo-secure-store`, `AsyncStorage` (legacy) | SecureStore for session tokens only. AsyncStorage holds theme preference and device id, both deliberately logout-protected. |
| HTTP | `axios` with the fetch adapter over nitro-fetch | Singleton `networkClient`; envelope contract (rule 8); hand-rolled 401 refresh mutex. |
| Fetching | `swr` | **SWR schedules; Zustand owns the data.** Keys are cache ids, not URLs. |
| Validation | `zod` | Auth `*Action` wrappers; `returnError` maps issues to form errors. |
| Flags | LaunchDarkly | Typed registry, never inline strings. |
| i18n | `i18next` | 18 namespaces, English only. |

**Two gotchas that bite hard:**

- SWR's **default fetcher is unauthenticated raw `fetch`**. Always pass an
  explicit fetcher.
- Overlays are **store-driven, not routes** — `useSheetStore`, `useModalStore`,
  `useGlobalLoaderStore`. Don't add a route for a sheet.

Environment variables are read **only** through `config/appConfig.ts`. Never
touch `process.env.EXPO_PUBLIC_*` anywhere else.

Exactly two React contexts are sanctioned: `BLEContext` (mounted only in the
device-onboarding layout) and `DeviceWebSocketContext` (app-wide, empty value —
it is a connection manager; UI reads `deviceControlStore`).

## i18n: eager vs deferred is load-bearing

Eight namespaces are statically imported in `i18n/index.ts`; the rest load via
`loadDeferredI18nNamespaces()`. This is not a performance preference.

`react-i18next`'s `bindI18nStore` is off, so `addResourceBundle` does **not**
re-render already-mounted screens. A deferred namespace on a first-paint
surface shows **raw keys permanently**, not briefly. And
`utils/device-onboarding-content.tsx` calls `i18n.t()` at module scope, which
Expo Router evaluates while building the route tree — those strings froze in
and no re-render could fix them.

**If you add a first-paint surface, its namespace must be eager**, and say why
in a comment beside the import, as the existing eight do.

Three namespace keys differ from their filenames: `deviceOnboarding` →
`device-onboarding.json`, `patchHome` → `patch-home.json`, `onboardingV2` →
`onboarding-v2.json`.

## Builds

Three environments — debug, beta, release — selected by env file, not by
gradle task:

```bash
npm run start:beta                # metro with .env.beta
npm run android:beta              # run on device
npm run android:clean:beta        # prebuild --clean + run
npm run android:apk:beta          # APK
npm run android:bundle:release    # AAB
npm run sync:tokens               # regenerate unistyles.ts
```

All three `android:apk:*` variants run `assembleRelease` — the suffix picks the
env file only.

**A clean rebuild is required** after changing `app.config.js`, `plugins/*`,
`native-modules/*`, env or package id, `google-services.json`, `nfctlog.aar`,
or the accent/menu colours in `unistyles.ts` (two config plugins read that file
at prebuild).

Real `.env.debug|beta|release` are gitignored — create them from the
`.env.*.example` files. `.env.local` is the ambient copy.

## What NOT to do

- Edit `android/` or `unistyles.ts`.
- Reorder `index.ts`.
- Read `process.env` outside `config/appConfig.ts`.
- Use SWR's default fetcher.
- Add a route for a sheet or modal.
- Trust counts in `DESIGN.md`, `CLAUDE.md` or `AGENTS.md` — all stale. Read the
  directory.
- Follow `AGENTS.md`'s pointers to `.cursor/commands/` — it does not exist.
- Reach for `hypnogram-chart-plan.md` while working in RN — it is a
  **React/Next.js, light-mode-only** spec sitting among eight RN porting
  guides.
- Search `.claude/worktrees/**`.
